# Repository Guidelines

## Project Structure & Module Organization

This repository is an Open Design live artifact, not a conventional app. The editable source lives at the project root:

- `template.html` is the HTML/CSS template with `{{data.path}}` bindings.
- `data.json` contains the canonical preview data.
- `artifact.json` describes artifact metadata and preview configuration.
- `provenance.json` records safe source and transformation notes.
- `.od-skills/live-artifact/` contains the local skill contract.
- `.live-artifacts/la-bunnies-cn-log-6fc7c8d7a495/` is the generated, deployable artifact. Its `index.html` is the file Vercel serves.

Do not treat `.live-artifacts/.../index.html` as the primary source. Update `template.html` and `data.json`, then regenerate through the Open Design workflow when available.

## Build, Test, and Development Commands

There is no package manager build step in this repo.

- `python3 -m json.tool data.json >/dev/null` validates root data JSON.
- `python3 -m json.tool artifact.json >/dev/null` validates artifact metadata.
- `rg -n "{{" .live-artifacts/la-bunnies-cn-log-6fc7c8d7a495/index.html` confirms the deployable HTML has no unresolved bindings.
- `python3 -m http.server 8000 --directory .live-artifacts/la-bunnies-cn-log-6fc7c8d7a495` previews the deployed artifact locally.
- `npx -y vercel@latest deploy .live-artifacts/la-bunnies-cn-log-6fc7c8d7a495 --prod --yes` deploys the generated artifact to Vercel.

## Coding Style & Naming Conventions

Use 2-space indentation for HTML, CSS, and JSON. Keep JSON keys lower camel case, matching existing names such as `lastUpdated`, `categoryKey`, and `refreshStatus`. Keep presentation rules in `template.html`; keep display content and repeated records in `data.json`. Avoid adding JavaScript unless it is necessary for interaction.

## Testing Guidelines

No automated test suite exists. Before publishing, validate JSON, check for unresolved template bindings, and run a local browser smoke test. Verify navigation anchors, responsive layout, external links, and the deployed URL returning `HTTP 200`.

## Commit & Pull Request Guidelines

The current history has one generated commit: `auto generated by opendesign`. For human changes, use concise imperative commit messages, for example `Update fan site data` or `Document deployment workflow`. Pull requests should include a short summary, changed source files, validation commands run, deployment URL when applicable, and screenshots for visual changes.

## Security & Configuration Tips

Do not store credentials, OAuth tokens, cookies, auth headers, or raw connector responses in any JSON file. Keep Vercel local state under `.vercel/` ignored inside the live artifact directory.
